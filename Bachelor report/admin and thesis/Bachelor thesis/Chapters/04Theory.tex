\section{Automatic Identification System (AIS)}
\label{sec:AIS}
% source: Kystverket AIS‑Norway description (project brief)
The Automatic Identification System (AIS) is a system that transfers navigation data, from an individual ship, to a base station on the norwegian coast, a satellite or between ships. 
However the system is prone to errors due to wrong configurations, area jamming, or message spoofing. Kystverket processes this data to detect errors in messages. In practice this pipeline identifies 60-80 million messages with errors every single day.

\section{Digital Twin}
% source: IBM “What is a digital twin?” https://www.ibm.com/think/topics/digital-twin

A digital twin is a digital representation of a physical object or system. An AIS digital twin primarily represents a ship's location and speed, but it also stores additional information such as the vessel type. The main purpose of a digital twin is to enable real time tracking and to provide historical data for further analysis in the future if needed \parencite{ibm_digital_twin}.

\section{Anomalies and Anomaly Groups} 
\label{sec:anomalies and anomaly groups}
Anomalies refer to detected irregularities from AIS messages. Messages sent from boats that are anomalous, are of differing types, including speed, unexpected maneuver, and jumping anomalies, where these pertain to if a ships message shows impossible distance covered, or speed. Anomaly groups are grouping of anomalies of similar type, into one group. These groups are created through grouping by proximity between anomalies.

\section{Software Engineering Principles}
Software systems are frequently designed after established, software engineer principles and methodologies, manufactured by pioneers in the field. The principles are created such that following them typically improves code quality and design of software. 

\subsection{Cohesion and Coupling}
Coupling and cohesion refers to a design principle for creating  sustainable and scalable code. Coupling refers to how tightly parts of the software depends on other parts, wherein if parts of the software have high coupling to other parts, then it will be harder to add and or change the project without it breaking. Cohesion describes if parts of the software are designed to fulfill a singular task, rather than being unfocused and serving multiple unrelated purposes. The goal for coupling and cohesion is to have high cohesion and low coupling, which in turn leads to better designed software\parencite{geeksforgeeks_cohesion_coupling}.

\subsection{Separation of Concerns}
Separation of concerns, is a software design principle, aimed at separating functionality, and system parts into cohesive units that solve specific concerns. This leads to independent parts of the system with specific responsibilities, leading to a more modular design\parencite{separation_of_concerns}.

\subsection{single responsibility principle}
The single responsibility principle dictates that a part of software, shall only have have one responsibility, such that code is modular and reusable. As a result of using this principle, code is easier to extend, becoming more manageable\parencite{single_responsibility}.

\subsection{Documentation}
Code documentation is the process of explaining through documentation with comments, how parts, methods and flow of a project works. Documentation is crucial for clarity and maintainability of code, whereas undocumented code carries confusion and unexplained complexity, leading to less effective development\parencite{ibm_documentation}.

\subsection{Refactoring}
Refactoring is an essential part of maintaining and creating good code. Refactoring is a restructure of already created code, where it is changed to better follow good design principles, while maintaining the same functionality. as a result of this, code becomes easier to maintain and extend, leading to the overall quality increasing\parencite{refactoring}.

\section{Project Management}
Project management refers to the process of coordinating and structuring the development process of a project. There are different project management styles, which aim to improve coordination, management, and overall effectiveness of the project.


\subsection{Agile Development}
Agile Development pertains to software development approaches emphasizing incremental development with early feedback. This creates a loop of development and feedback that ensures projects avoid unecessary, unguided work on superfluous systems or features. There exists agile methods that are frameworks, giving guidance on how to develop following the agile principles, the most common one being Scrum\parencite{agile_microsoft}.


\subsection{Scrum Framework}
Scrum is a project management framework designed after agile principles. Scrum emphasizes iterative development by segregating work into an iterable time-period called a sprint cycle. following the scrum framework requires having specific roles, including scrum master, which coaches and monitors the scrum process in a project. product owners, being the ones the project is created for, and the core feedback loop. The development team is the last role, consisting of a small development team responsible for the implementation of the project, following the Scrum framework.

The work in a scrum project, is represented through scrum artifacts, being sectioned in three distinct parts. Sprint backlog is the features and requirements the product owner requires to be done. Sprint backlog is features, bugs and implementations being worked on for a team's current sprint cycle, that is intended to be complete by the end of a cycle. An increment is an end goal of a sprint. 

Sprints are executed as time-boxed iterations where the development team works on selected backlog items. A sprint itself is planned beforehand, setting the goals to be worked on in the project. after a sprint is worked on, a sprint review and retrospective is held. The review being a informal showcase of the work done, while a retrospective is a review of the sprint itself, clarifying the strengths and weaknesses the current sprint had. Sprints are normally worked on in a weekly or biweekly timetable, with frequent feedback from the product owner. 

A system that is mostly utilized by developers is a daily Scrum or as a more general term a daily stand up. This system is a time every day that happens once a day when all or most developers have shown up to work. This meeting is set up for developers to discuss what problems they are working on and what issues they have run into, however the max time spent in this meeting is only 15 minutes. Then using this discussion the next 24 hours of work can be planned, while also letting developers have an easier time discussing problems they have with other members with expertise\parencite{atlassian_scrum,agile_academy_daily_standup}

\subsection{Supercluster.js}
\label{sec:supercluster}

Clustering is done through the hierarchical greedy clustering method, grouping points based on radius around various points chosen from the dataset. Performance of the library is gained by reusing previous clustering calculation, leading to increased performance in zoom and drag operations reusing past data\parencite{mapbox_supercluster_github ,mapbox_supercluster_blog}.
