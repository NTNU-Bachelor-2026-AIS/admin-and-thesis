\textit{This chapter outlines the results of the project, explaining the functionality and design of the completed project.}


\section{Project overview}

The application is a locally hosted, visualization software, designed to visualize anomalies and anomaly groups. Multiple visualization methods requested by customer are implemented, to a degree found satisfactory to the customer. 

The project itself is developed following general coding standards such as single responsibility and coupling and cohesion, to the best of the groups ability, with refactoring having been done multiple times throughout the project to better follow these standards. 

The end result has completed functionality that the customer has wanted throughout the project, as the project developed the requests changed, leading to the end functionality being the main core of what the customer wanted to test as concepts. The specifics on the implementation were chosen by the group members, such as technology choice, outside of requested uses such as react and a map provider choice being guided.

\section{Visualisation Results}
All visualisation methods described in the Method chapter were implemented in the final system. The system includes clustering, heat map, anomaly group visualisation, individual anomaly visualisation, and base station visualisation. Additional proposed features were not implemented


\subsection{Base Station Visualization}
A base station layer is is part of the application, implemented as mentioned in section \ref{sec:base_station}. The base station layer is visualized through blue icons in figure \ref{fig:base_station_result_image}. The base station layer itself is persistent, meaning that it is a visualization layer that will always be present in the app, even if other methods of visualizing the data points are changed. 
\begin{figure}[H]
    \centering
    \includegraphics[width=0.4\textwidth,height=0.2\textheight,keepaspectratio]{Figures/Base-station-view.png}
    \caption[base station view]{Base station layer}
    \label{fig:base_station_result_image}
\end{figure}
Base stations are linked to anomalies through backend data representing transmissions from individual anomalies. This is then used in other layers to connect base stations to anomalies through signal strength. The base stations data itself will never change in position, as they are static points on the map. This provides persistent reference in relation to anomaly and transmitted base station, and helps end users visually observing the distance between anomaly cluster and base station, Leading to visual feedback on the spatial relationship between anomalies and base stations.

\subsubsection{Clustering Visualization}
As described in section \ref{sec:clustering_method}. The clustering approach is implemented with Supercluster.js calculating clusters through proximity based on radius, and zoom level (Section \ref{sec:supercluster}). This approach produces grouped anomaly points, with numeric labels indicating the number of anomalies in each cluster, as shown in Figure \ref{fig:clustering_result_image}. 
\begin{figure}[H]
    \centering
    \includegraphics[width=0.4\textwidth,height=0.35\textheight,keepaspectratio]{Figures/clustering-result.png}
    \caption[Clustering result image]{Result clustering visualization}
    \label{fig:clustering_result_image}
\end{figure}
Clustered view allows for user interaction through zooming and dragging the viewable map area, where clusters outside of the view on the map, are not displayed. When the application is more zoomed out, the clusters are aggregated into fewer larger groups. Clusters are calculated based on a radius of 40 pixel around a point, aggregating based on radius, and zoom level. Zoomed in the clustered views shows smaller aggregation of clusters, as the anomaly groups have greater distance between, leading to a greater number of clusters, with the opposite being true for lower zoom levels. 


\subsection{Heat Map Visualization}
The system includes a heat map visualization layer, The heat map is implemented as in section \ref{sec:Heat_Map_method}. An example of the implemented heat map visualization is shown in figure
\ref{fig:heatmap_result_image}.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.54\textwidth,height=0.35\textheight,keepaspectratio]{Figures/heatmap-result.png}
    \caption[heatmap result image]{Heat map result }
    \label{fig:heatmap_result_image}
\end{figure}
Color is generated through calculating the sum of points inside a radius of 40 pixels, meaning points inside a circle are calculated as a sum, leading to higher density of points being weighted more.\url{https://deck.gl/docs/api-reference/aggregation-layers/heatmap-layer}. 
The resulting heat map layer allows for zoom and drag operations to change the heat map view dynamically, with zoomed in levels having less dense representation, while zoomed out levels lead to higher aggregates per pixel radius, and denser representation overall.

Individual anomaly group visualization is created as shown in figure \ref{fig:anomaly_group_result_image}.
\begin{figure}[H]

The layer shows an info component for the current group, with coordinates and start date, with type of anomaly. Signal strength is visualized through the lines, connecting the individual anomalies inside the group to the base stations shown in the picture as blue symbols. The info component allows for users to show anomalies inside the group, through button press on the component, leading to the visualization being changed to the individual anomaly visualization.

Individual anomalies, are shown as a scatterplot, section \ref{sec:scatter_plot}. The visualization shows the points colored based on signal strength, from red to green. This is done through the signal strength value being normalized from 0 to 1, in the database.

Figure \ref{fig:individual_anomaly_result_image}, shows the completed layer. anomalies are correctly colored through the signal strength variable, with an info component being shown for an anomaly, through clicking on it. The info component illustrates features of the anomaly, like it's direction, name, and MMSI.
