The system follows a client-server architecture. The backend is written in Go and runs inside a Docker container that exposes a REST API. Swagger is used for API documentation. The frontend is built with React and TypeScript and gets the data it needs through API calls to the backend.

\subsection{Backend and Data Flow}

The backend infrastructure and test database were provided by the customer, pre-populated with test data since actual AIS anomaly data is confidential. The team's main contribution to the backend was a master query endpoint. This endpoint accepts all filter parameters (anomaly type, mmsi, and time range.) and returns only the matching data. Instead of getting all the anomaly groups and filtering on the frontend, all variables get sent to the backend which queries the data again. This was done since keeping old data and filtering client-side was slow and inefficient.

\subsection{Map Setup and Rendering}

The map interface is built using MapLibre GL JS, which leverage's WebGL for GPU-accelerated rendering directly in the browser. GPU acceleration is important since rendering tens of thousands of data points using only the CPU makes the website less responsive cause of lag.

\subsection{Clustering}

The frontend uses MapLibre's built-in clustering to dynamically aggregate nearby anomaly points based on the zoom level of the user. At lower zoom levels clusters display a count label showing the number of aggregated points. As the user zooms in the clusters break apart into smaller groups and eventually into individual scatter points. This perserves both scale perception and point accuracy.

\subsection{Heat Map}

A heat map layer was implemented as an alternative visualisation mode, toggled via the filter. The heat map uses colour gradients to show point density, which enables operators to quickly locate hotspot areas of anomaly concentration.
