\section{Background}
Norway manages one of the world's most extensive coastlines, and the \gls{nca} is the national agency responsible for coastal management, maritime safety, and emergency preparedness \parencite{kystverket_nca_role}.
A central part of this is monitoring of sea-faring vessels. This is done through the use of \acrfull{ais}, a messaging system that transmits information about a vessel, including its heading and location.
These messages are handled by "\acrshort{ais} Norway" which is a national tracking network operated by the \acrshort{nca} that combines around 90 shore base stations and a few \acrshort{ais} satellites \parencite{kystverket_ais_norge}.
Even though it was originally developed as a anti-collision tool, the \acrshort{ais} is now a critical part of the infrastructure for \acrfull{vts}, search and rescue operations, and environmental protection \parencite{barentswatch_ais_status_report}.


While the \acrshort{nca} currently utilizes analytical tools to identify deviations in \acrshort{ais} data, the existing solutions lack advanced visualization capabilities such as heat maps, clustering and temporal analysis. These features are essential for operators to gain proper insight into the anomalies, because of the massive scale of data. Every day millions of \acrshort{ais} messages are flagged as anomalies, which makes it hard for operators to differentiate between anomalies that are technical issues and potential security threats. To solve this issue, the \acrshort{nca} hopes for a more intuitive, web-based prototype with new visualization methods \parencite{kystverket_ais_norge}.

\section{Objective}

The objective of this project is to develop a web-based program that can visualise \acrshort{ais} anomaly data to provide maritime experts with improved insights. The program will also serve as a tool for both live monitoring and historical analysis.

\textbf{Specific goals include:}
\begin{itemize}
\item \textbf{Advanced Map Visualization:} Implementing a map interface using MapLibre to display anomaly clusters, satellite paths, and base station locations.

\item \textbf{Data Aggregation and Clustering:} Developing methods to handle high-density data without overwhelming the user interface.

\item \textbf{Temporal Analysis:} Provide a time-based feature that allows users to visualize data forward and backward in time to observe development of anomalies.

\item \textbf{Efficient Querying:} Building a bridge between the React frontend and the backend database to allow users to filter data by ship type, anomaly category, and time intervals.
\end{itemize}

\section{Requirements}

The requirements for the project were developed in communication with the customer. There are multiple functional and system requirements. 



\subsection{Functional Requirements}

Functional requirements from the customer include support for new visualization methods such as clustering and heat maps. The system must also include filtering and anomaly representations displaying signal strength, position and anomaly type. 


\subsection{System Requirements}

The solution will be implemented as a local database and a website that can query and visualize the stored data. All data processing will be handled on the device hosting the database. 
\begin{itemize}
\item \textbf{Frontend:} Must be built using React and TypeScript
\item \textbf{Map Engine:} Must utilize MapLibre or an equivalent library used by the \acrshort{nca}.
\item \textbf{Data Querying:} The application must be able to query a database to handle the large amounts of data.
\end{itemize}
