\section{Background}
Norway manages one of the world's most extensive coastlines, and the \gls{nca} is the national agency responsible for coastal management, maritime safety, and emergency preparedness. % Ref to https://www.kystverket.no/en/about-us/what-is-the-role-of-the-nca/
A central part of this mission is "\acrshort{ais} Norway" which is a national tracking network operated by the \acrshort{nca} that combines around 90 shore base stations with a few \acrshort{ais} satellites. %https://www.kystverket.no/en/sea-transport-and-ports/ais/ais-norge/
Even though it was originally developed as a anti-collision tool, the \acrfull{ais} is now a critical part of the infrastructure for vessel traffic services, search and rescue operations, and environmental protection. %https://www.kystverket.no/en/about-us/what-is-the-role-of-the-nca/, https://www.barentswatch.no/en/articles/ais-displays-status-report-at-sea/


While the \acrshort{nca} currently utilizes analytical tools to identify deviations in acrshort{ais} data, the existing solutions lack advanced visualization capabilities such as hexagonal binning and temporal analysis. These features are essential for operators to gain proper insight into the anomalies, because of the massive scale of data. Every day around 60-80 million messages are flagged as anomalies which makes it hard for operators to figure out which anomalies are technical issues and which are security threats. To solve this issue, the \acrshort{nca} hopes for a more intuitive, web-based prototype with more advanced analytical tools such as hexagonal binning, heat-maps and temporal analysis.% https://www.kystverket.no/en/sea-transport-and-ports/ais/ais-norge/

\section{Objective}

The objective of this project is to develop a web-based program that can visualise \acrshort{ais} anomaly data to provide maritime experts with better usable insights. The program will also serve as a tool for both live monitoring and historical analysis.

\textbf{Specific goals include:}
\begin{itemize}
\item \textbf{Advanced Map Visualization:} Implementing a map interface using MapLibre to display anomaly clusters, satellite paths, and base station locations.

\item \textbf{Data Aggregation and Clustering:} Developing methods to handle high-density data without overwhelming the user interface.

\item \textbf{Temporal Analysis:} Provide a time based feature that allows users to visualise data forward and backward in time to observe development of anomalies.

\item \textbf{Efficient Querying:} Building a bridge between the React frontend and the backend database to allow users to filter data by ship type, anomaly category, and time intervals.
\end{itemize}

\section{Motivation}

During a normal day the \acrshort{nca} gets around 80 million \acrshort{ais} messages. From these messages millions can become flagged as anomalies. 

The team chose to work on "Visualisation of \acrshort{ais}" Anomaly Detection" because it addresses a critical real world problem while utilizing modern technical solutions. Maritime security is a field of immense societal importance in Norway. Therefore we believe contributing a prototype to the \acrshort{nca} is a very meaningful purpose for our work.

Furthermore, we are particularly interested in the challenges of Data Processing and Visualisation as well as Front End Functionality. Even so, handling 80 million data points in a web browser presents a significant technical hurdle. However, because of our groups experience in web development and data processing we believe this project allows us to apply those skills in a large scale problem.

\section{Requirements}

The requirements for the project were developed in communication with the customer. There are multiple functional and system requirements. 



\subsection{Functional Requirements}

Functional requirements from the customer, include support for new visualization methods such as clustering and heat maps. Also will the system need to have filtering and anomaly representations that give information about signal strength, position and anomaly type. 


\subsection{System Requirements}

The solution will be implemented as a local database and a website that can query the data it needs and visualise that information. All data processing will be handled on the device hosting the database. 
\begin{itemize}
\item \textbf{Frontend:} Must be built using React and TypeScript
\item \textbf{Map Engine:} Must utilize MapLibre or an equivalent library used by the \acrshort{nca}.
\item \textbf{Data Querying:} The application must be able to query a database to handle the large amounts of data.
\end{itemize}
